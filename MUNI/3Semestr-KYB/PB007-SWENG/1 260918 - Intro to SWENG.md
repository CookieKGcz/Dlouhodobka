## IEEE definition of sweng
- "The application of a systematic, disciplined, quantifiable approach to the development, operation, and maintenance of software; that is, the application of engineering to software"
	- systematic - Intentional, repeatable ways of working
	- disciplined - Agreed practices followed by teams
	- quantifiable - Evidence, measurement, feedback
	- development, operation, maintenance - the whole lifecycle
## SWENG concerns:
- source code
- requirements and specifications
- architecture and design documents
- tests and test data
- deployment and configuration
- operational procedures
- user and maintainer documentation
- the whole product/service in use as a software system
## System modeling
- the process of developing abstract models of a system.
	- models present different views or perspectives of that system
## UML
- unified modeling language
- Standardized visual language for modelling software systems.
- Focus on detailed analysis and design

- Advantages
	- Mature and well-known
	- Standardized notation
	- Expressive
	- Tool support
- Disadvantages
	- Complex notations
	- Less explicit connections between diagrams
	- Too technical for non-developers
## SysML
- Focus on modelling of cyber-physical systems
- Extension of UML
- Additional parameters for model execution

- Adv
	- Covers hw, sw and people
	- Better traceability of requirements
	- Better system functional decomposition
	- Integration with other engineering models
- Disadv
	- More complex then UML
	- Diff to learn
	- Heavyweight tools
## C4 model
- Context, containers, components, code
- Designed for wider understandability and communication

- Adv
	- Easy to learn
	- Explicit levels of abstraction
	- Lightweight
	- Good for agile development
- Disadv
	- Missing many types of models (e.g. for behavior modelling)
	- Less formal specification/semantics
## ArchiMate
- Enterprise architecture modelling lang
- Describes relationships between business, application and technology

- Adv
	- Rich options for description of dependencies and relationships
	- Useful for architecture roadmaps
	- Standardized
- Disadv
	- Large and complex notation
	- Overkill for normal simple systems
